# 研发工作台规格文档

Status: resolved

## 问题陈述

电商中台管理者无法有效核实团队成员的代码产出和项目进度。现有的 Git 提交数据散落在 Codeup，难以聚合和观察：
- 无法实时掌握每个成员每日的工作内容和工作量
- 同一个成员用多个 Git 邮箱提交，难以统一追踪
- 无法快速发现团队中持续无活动的成员
- 项目级别的进度趋势不清楚

## 解决方案

在 PSP 所在的 Frappe site 上部署独立 app `dev_workbench`（研发工作台），从 Codeup 定时拉取提交数据，汇聚成四个看板视图供管理者查看：

1. **成员日报**：每个成员每天的提交列表和 AI 生成的摘要
2. **缺勤提醒**：连续 2 个工作日无提交的成员，支持"请假豁免"
3. **项目活跃度**：过去 12 周按周统计的提交趋势折线图
4. **飞书日报**：每个工作日早上 9 点私聊推送，汇总前一天的活动和缺勤者

管理者无需登录页面，日报消息就能了解情况；需要详细查看时打开页面切换统计范围或查看历史数据。

## 用户故事

1. 作为管理者，我想每天早上看到一条飞书日报，这样我不用打开网页就能掌握团队整体进度
2. 作为管理者，我想看到每个成员今天的提交摘要（格式：改了什么、涉及几个仓库、多少行代码），这样我快速了解大家在做什么
3. 作为管理者，我想按项目来看代码活动，这样我能对标不同业务线的进度
4. 作为管理者，我想在有人连续 2 个工作日无提交时收到提醒，这样我能及时跟进是不是有问题
5. 作为管理者，我想把同一个人的多个 Git 邮箱归到一个"成员"下，这样提交数据不会被拆散
6. 作为管理者，我想标记某个成员的某几天为"请假豁免"，这样缺勤提醒不会误报
7. 作为管理者，我想在看板上切换"全部分支"和"仅默认分支"，这样既能看到所有开发中的工作，也能看到已合并的成果
8. 作为管理者，我想手动添加和修改项目分组（哪些仓库属于哪个项目），这样可以按业务线而不是按代码库来管理
9. 作为管理者，我想点一个"立即刷新"按钮获取最新数据，这样不用等轮询周期就能看到最新进度
10. 作为管理者，我想看到项目活跃度的 12 周趋势图，这样能判断项目是在加速还是减速
11. 作为管理者，我想在日报中看到"未归属提交"（无法映射到成员的提交），这样能发现配置问题或新成员
12. 作为管理者，我想通过飞书日报中的链接打开看板，这样可以快速跳到详细页面
13. 作为管理者，我想查看历史日报（过去 N 周的归档），这样能对比进度变化
14. 作为管理者，我想看到每个成员的 Git 身份列表和关联状态，这样知道哪些邮箱已经被认领、哪些还没有

## 实现决策

### 数据模型

- **Project（项目）**：管理者创建，包含多个 Codeup 仓库；属于项目的所有提交会被聚合统计
- **ProjectMember（项目成员）**：从飞书通讯录导入，一个成员在一个项目中可以有多个 GitIdentity；全局成员表
- **GitIdentity（Git 身份）**：作者邮箱或用户名，关联到某个 ProjectMember；支持一个成员多个身份、一个身份多个成员的中间状态
- **CodeupRepository（仓库配置）**：存储 Codeup 仓库信息（org、repo id、access token 来源）和排除文件规则（glob 列表）
- **DailyActivityLog（日志）**：每个成员每天的汇总数据（提交数、行数、文件数、原始数据），用于展示历史和日报归档
- **DailyReport（日报记录）**：每个工作日生成一条，记录推送时间、飞书消息 id、内容摘要，用于撤回和存档

### 数据流

1. **定时轮询**（每 30 到 60 分钟）：
   - 遍历所有 Project 和关联的 CodeupRepository
   - 调用 Codeup OpenAPI 的 ListCommits，按分支和时间范围筛选
   - 通过 commit.parentIds 识别 merge commit（长度 > 1），排除它们
   - 按 commit hash 去重（一个 hash 在多分支上只算一次）
   - 尝试按 GitIdentity 映射到 ProjectMember；无法映射的放进"未归属"

2. **AI 摘要生成**：
   - 每个成员每天的提交集合作为输入
   - 提取提交信息、变更文件列表（排除规则已应用）
   - 调用配置的 OpenAI 兼容 API，prompt 要求生成一句话摘要
   - 摘要结果存到 DailyActivityLog

3. **缺勤判断**：
   - 每个工作日晚上遍历所有 ProjectMember
   - 检查过去 2 个工作日的 DailyActivityLog 是否都没有提交
   - 如果都没有且没有豁免记录，标记为缺勤

4. **飞书日报推送**（每个工作日早上 9 点）：
   - 聚合前一工作日的 DailyActivityLog 和缺勤记录
   - 按 Project 分组，生成卡片消息（每个项目一栏）
   - 用应用机器人私聊发给管理者（用 open_id）
   - 记录到 DailyReport 表

### 页面结构

- **Dashboard（主看板）**：四个 tab（成员日报、缺勤提醒、项目活跃度、日报归档），统计范围切换（全部分支/默认分支）和立即刷新按钮
- **ProjectSettings（项目配置）**：管理项目和关联的仓库，配置排除文件规则
- **MemberSettings（成员配置）**：列出飞书通讯录成员，显示 Git 身份关联状态，支持手动认领和添加新身份
- **RepositoryConfig（仓库配置）**：Codeup 令牌管理、仓库关联、排除规则编辑
- **AbsenceExemption（请假豁免）**：日期选择器，标记成员的请假日期

### 后端 API

- `GET /api/activity/daily/<member_id>/<date>`：获取某成员某天的提交列表和摘要
- `GET /api/activity/project/<project_id>/trend`：获取项目过去 12 周的周趋势数据
- `GET /api/absence/list/<date>`：获取某日的缺勤成员列表
- `POST /api/sync/trigger`：手动触发一次 Codeup 数据同步（权限：仅管理者）
- `POST /api/feishu/test`：发送测试日报消息到飞书（权限：仅管理者）
- `GET /api/codeup/identities/unclaimed`：获取未关联的 Git 身份列表
- `POST /api/member/claim-identity`：管理者为某个成员认领一个 Git 身份

### Codeup 集成

- 使用 OpenAPI（新版）而非 Webhook；鉴权方式：个人访问令牌在 `x-yunxiao-token` 请求头
- 令牌过期前 7 天飞书提醒管理者续期
- API 调用时遵循 Codeup 的限流策略（429 时指数退避重试）
- 提交数据不含行数时，补调单个提交详情接口；仍未获得则标记"行数未知"

### 飞书集成

- 使用应用机器人（而非自定义 bot），私聊发给管理者（receive_id_type: "open_id"）
- 日报消息为交互卡片，包含：
  - 前一工作日的日期
  - 按项目分栏，每栏包含成员的提交摘要（提交数、行数、文件数 + AI 摘要）
  - 单独一栏列出缺勤成员（醒目标记）
  - 页面链接（指向该天的详细看板）
  - "未归属提交"数量提示

### AI 摘要配置

- 模型服务商通过 OpenAI 兼容接口配置（基础 URL、API Key、Model Name）
- 支持本地修改配置以切换服务商或内网模型
- 输入格式：commit message 列表 + 变更文件列表（不含 diff）
- 输出要求：单句话摘要，不超过 100 汉字

### 排除文件规则

- 默认排除规则内置：`*.lock`、`package-lock.json`、`yarn.lock`、`pnpm-lock.yaml`、`dist/**`、`build/**`、`public/**`、`*.min.js`、`node_modules/**`
- 每个 CodeupRepository 可追加项目级别的自定义规则（glob 列表）
- 被排除的文件仍在文件列表中显示，只是不计入行数统计

### 权限

- 只有飞书通讯录中被标记为"管理者"的成员能看到工作台
- 非管理者无法看到此 app 的菜单和页面
- 前端路由和后端 API 都需要鉴权

### 提交日期定义

- 按 commit 的 author date（作者时间），不是 committer date
- 时区固定为北京时间（UTC+8）
- 工作日按国家法定节假日日历计算（通过飞书日历或内置配置）

## 测试决策

### 测试策略

最高层的测试应验证端到端的用户流程：

1. **每日推送流程测试**：
   - 验证定时任务在指定时间触发
   - 验证 Codeup 数据成功拉取、去重、映射
   - 验证 AI 摘要成功生成
   - 验证飞书消息成功推送，格式正确
   - 验证 DailyActivityLog 和 DailyReport 被正确保存

2. **页面显示测试**：
   - 验证成员日报视图展示的数据与 DailyActivityLog 一致
   - 验证缺勤提醒视图正确识别 2 天无提交的成员，豁免记录生效
   - 验证项目活跃度视图的 12 周趋势数据准确
   - 验证统计范围切换（全部/默认分支）改变了显示的数据

3. **数据映射测试**：
   - 验证同一成员的多个 Git 身份被正确关联
   - 验证无法映射的提交进入"未归属"
   - 验证新身份认领后重新计算历史数据

### 被测模块

- **Codeup 同步模块**：API 调用、数据转换、去重逻辑、成员映射
- **摘要生成模块**：AI 调用、prompt 构造、缓存
- **飞书推送模块**：消息格式、时间点、错误处理
- **缺勤判断模块**：工作日计算、豁免规则应用
- **权限检查模块**：管理者鉴权、非管理者拒绝

### 先例

- PSP app 的飞书登录集成是参考
- Frappe Scheduled Task 的测试方式
- Vue 3 + frappe-ui 组件测试（单测 + E2E）

## 不在范围内

- 任务管理功能（后续板块，但预留字段以支持）
- 代码库权限管理（假设访问令牌有权限的仓库都可见）
- 自定义工作日日历（使用国家法定节假日，不支持团队级别定制）
- 实时数据推送（只支持定时轮询，无 webhook）
- 移动端适配（假设通过飞书日报在移动端查看，网页页面为桌面设计）
- Codeup 之外的代码平台集成（第一版仅 Codeup，后续可按模式扩展）

## 进一步说明

- **部署**：app 代码应单独创建一个 Codeup 仓库 `dev_workbench`，通过 `apps.json` 配置构建进 frappe_docker 镜像
- **开发环境**：复用 frappe_docker 的 devcontainer，PSP 的 Feishu 配置和 Codeup 令牌可直接使用
- **数据同步起点**：首次部署时回溯 90 天历史提交；更早的数据需要手动补拉
- **发布版本**：与 PSP 配套发版，版本号同步
