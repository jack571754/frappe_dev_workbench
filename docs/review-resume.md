# 全项目审查断点恢复

扫描检查点保存在执行器数据目录的 `checkpoints/`，不会随临时容器或 attempt 清理。
任务、仓库、提交 SHA、检查点版本、材料摘要、OCR 版本、模型和服务地址共同决定检查点身份。
源码仍只读挂载；仅隔离的 OCR 状态目录允许写入。状态目录父级仅当前用户可访问，容器通过附加组写入状态目录。

- “继续审查”：重新领取任务并通过 OCR `scan --resume` 复用已完成文件。没有旧检查点时开始首次扫描。
- “重新开始”：递增检查点版本，新建会话，不删除旧报告。
- 心跳遇到临时连接错误或 502/503/504 最多重试三次；认证失败和其他业务写入不会自动重试。
- 扫描任务租约失效后最多自动恢复三次，再次失败需人工处理；取消任务不会自动恢复。
- 执行器重启后通过正常轮询重新领取过期任务，继续使用此电脑保存的检查点。更换电脑不保证有相同检查点。
- 升级前使用临时 HOME 的任务无法恢复已删除的会话。提交审查暂不启用会话持久化。

验证：执行器单元测试、真实数据库事务回滚测试、Vite 构建，以及两个独立容器中的合成单文件扫描与恢复。
容器实测恢复记录包含 `resumed_from`、`reused_files: 1`，恢复扫描 token 使用量为 0。

检查点含代码审查信息，应随数据目录一起保护。当前不自动删除检查点，磁盘空间需按实际使用管理。
