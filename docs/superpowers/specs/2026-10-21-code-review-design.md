# 研发工作台：Claude Code 只读代码审查设计

日期：2026-10-21  
状态：待用户审阅；本文不代表实现已完成。

## 目的与已确认范围

管理者从成员日报选择提交，使用当前 Windows 电脑上的 Claude Code 初审代码，再在工作台逐条复核问题，在线下反馈给成员。只向代码仓库读取数据，不修改代码，不发布评论，不创建仓库任务，不提交、推送或合并。审查记录只保存在工作台。

第一版手动发起，执行器并发数为 1。暂不实现每日自动审查、Codex 接入、自动修复、仓库反馈或修复状态同步。不根据问题数量给成员评分。

## 当前依据

- 工作台为同一 Frappe site 上的 `dev_workbench` app，前端为 Vue；现有日报路由为 `/dashboard/daily-activity`。
- 已有成员、Git 身份、项目、代码仓库、提交活动及 Codeup 客户端可复用。客户端已有提交列表和提交详情方法，差异和版本文件读取能力仍需核实。
- 本机已安装 Claude Code 2.1.306。通过本机 `claude --help` 确认具有非交互输出、JSON Schema、工具集合限制、restricted、安全模式等选项；尚未验证认证、模型可用性及组合参数行为。
- ADR-0001 的同站点部署、ADR-0002 的轮询方向保持适用。
- ADR-0003 禁止提交摘要向模型发送代码。代码审查会发送代码，是新的用途例外，必须在实现时用独立 ADR 明确其边界；提交摘要继续遵守原决策。用户已选择 Claude Code，代码发送到其实际配置的模型服务，不等于仅在本机推理。

## 使用流程与页面

1. 成员日报每行增加“AI 审查”。打开选择框时带入成员、北京时间提交日期、项目、仓库和统计范围，列出明确的 SHA，供管理者选择。
2. 第一版按单个非合并提交分别审查；批量选择产生多个任务，界面展示批次。这样不会将其他成员夹在提交区间内的改动归到被选成员。后续再支持明确 base/head 的整体审查。
3. 每个任务固定 head SHA，普通提交使用其父提交为 base；根提交以空树为 base。合并提交第一版提示暂不支持。代码和 diff 均按固定版本读取。
4. 新增 `/dashboard/code-review` 任务列表及 `/dashboard/code-review/:id` 详情。列表展示成员、项目、仓库、SHA、执行状态、待复核数、已确认数及时间。
5. 详情左侧为文件列表，中间为差异和可展开上下文，右侧为问题及人工复核区。旧侧删除行与新侧新增行明确区分。
6. 管理者确认或忽略问题，添加备注，标记已线下反馈；复制内容默认只包含已确认问题、仓库、SHA、路径与行号。复制不触发任何对外发送。

## 组件与数据流

工作台前后端 → Frappe 审查任务队列 ← Windows 执行器 → Claude Code 子进程。

执行器主动轮询工作台，不开放本机入站服务。使用独立机器凭证，经认证 API 领取任务、上报心跳、上传结果。机器凭证只能访问被分配的审查任务和相应代码材料，不能管理成员、修改业务数据或冒充管理者复核。

代码准备由受信任的执行器完成：按仓库白名单解析远端，读取指定 SHA 的 diff 与版本文件，在独立任务目录形成代码快照；不得操作管理者正在开发的目录。优先复用服务器受控的代码读取能力；若采用本机只读 Git 镜像，凭证必须独立配置且具备最小读取权限。两种获取方式不同时实现，实施计划根据 Codeup 能力核实结果选定一种。

Claude Code 只看到去除 `.git`、凭证、环境配置和无关本地文件的审查材料。执行器凭证、Codeup 凭证不出现在提示词、命令参数或输出日志中，子进程环境也不继承这些凭证。

## Claude Code 调用边界

复用 CLI 的模型调用与代码搜索能力，不自建智能体循环。每次任务使用全新会话、固定工作目录，通过 stdin 提供审查要求，使用 JSON Schema 约束结果，并保存受限的原始报告以便解析失败时查看。

实现时验证以下组合：非交互模式，仅开放 Read、Glob、Grep，restricted 模式，不允许 Edit、Write、Bash、PowerShell、浏览器、MCP、插件、钩子或子智能体。禁用会话持久化与项目自定义指令，禁止 bypassPermissions。以安全模式及显式工具集合限制为基础，具体参数以当前 CLI 验证为准。

工具白名单限制能力，不能单独证明文件系统隔离。执行器必须将模型可读目录限制到快照，并提供操作系统层面的只读边界；认证数据按 Claude Code 所需最小范围单独提供。Windows 可行机制需在实施前验证；若无法证明模型不能读取任务外文件或写入源码，则不启用生产审查，不能用“提示词要求只读”替代。

仓库中的 README、CLAUDE.md、注释和其他内容都视为待审查数据，不能覆盖执行指令。不得执行构建、测试、依赖安装或仓库脚本；本流程提供静态审查，不声称运行验证。

提供任务超时、输出长度、上下文读取量和可配置预算限制；预算选项是否适用于当前认证方式需实测，始终使用独立超时兜底。初始超时建议 20 分钟，执行器轮询 10 秒、心跳 15 秒、租约 90 秒，均允许配置。

## 数据模型与输出契约

### 审查任务

保存创建者、成员、项目、仓库、head/base SHA、批次、执行状态、复核状态、执行器、attempt、租约令牌、工具版本、模型标识（可获取时）、审查规则版本、开始结束时间、覆盖情况、错误原因和原始报告。

### 审查问题

保存所属任务及 attempt、严重程度（高/中/低/建议）、标题、文件路径、代码侧（old/new）、起止行号、触发条件、影响、代码证据、修改建议、不确定性、人工结论（待确认/已确认/已忽略）、复核者、备注和线下反馈时间。

### 报告

包含 `schema_version`、`summary`、`findings`、`coverage`、`limitations`。覆盖情况列出已审查、跳过和读取失败文件及原因；二进制、超大文件和被排除文件不能静默算作已审查。统计排除规则不直接等同于代码审查排除规则。

服务端校验路径属于快照、行号属于对应版本、严重程度和字段合法。无法验证的位置作为未定位发现显示，不制造可点击的错误行号。报告解析失败保存原文并标记失败；空发现只有在完整覆盖且执行成功时才显示“AI 未发现问题”。

## 状态、并发与重试

执行状态：排队中 → 准备代码 → 审查中 → 已完成 / 部分完成 / 失败 / 已取消 / 已中断。

复核状态独立为：未复核、复核中、已复核；AI 完成不自动代表人工复核完成。问题数为零仍需人工确认后才能成为已复核。

领取操作使用原子更新及租约，服务端拒绝过期令牌的心跳和结果。执行器离线时未领取任务保留排队，并显示等待执行端上线；已领取任务租约过期标为中断，第一版由人工重试，避免重复付费。取消时终止对应子进程，迟到结果不得覆盖当前状态。

幂等键包含仓库标识、base/head SHA、审查规则和配置版本；同一创建者、同一可见范围内重复点击复用任务，避免跨权限泄露。强制重新审查创建新 attempt，保留旧报告与人工结论，不自动继承问题的确认状态。

## 权限与保存

复用 Frappe 登录体系，但为发起、查看、复核、配置执行器设置显式服务端权限校验。默认创建者及明确授权的审查管理者可见；成员不能因为是提交作者自动查看审查记录。API、下载和原始报告都遵守相同规则。

展示代码和报告时按纯文本转义，禁止执行 HTML。审查快照成功上传后清理，失败任务默认保留不超过 24 小时用于重试；建议报告和私有备注保存 90 天并支持管理员配置。清理只作用于执行器专用根目录下经过校验的任务路径。

## 验收标准

- 从日报发起指定提交审查，Claude Code 返回带代码依据的问题，工作台能够确认、忽略、备注和复制已确认问题。
- 同一提交跨分支不重复创建等价任务，批量选择不会混入其他成员提交范围。
- 任意一次审查均未改变源代码、仓库远端、现有工作目录或复核记录；通过受控写入尝试、任务外读取尝试和脚本执行尝试验证边界。
- 断网、电脑离线、超时、取消、重复领取及迟到结果具有确定行为；CLI 认证失败提供可操作原因，不无限重试。
- 无问题、部分覆盖、解析失败、人工已复核能够明确区分。
- 未授权账号不能读取任务、代码、原始报告或修改复核结论；凭证不出现在报告和日志。
- 提交摘要及现有日报功能继续遵守 ADR-0003。

## 实施前验证项

验证 CLI 登录及实际模型服务、非交互调用与结构化结果、Windows 目录隔离、禁用自定义能力、仓库固定版本读取方式。验证使用合成代码，不读取真实成员源码，不产生对仓库的写入。任一关键隔离能力未通过时先调整执行边界，再开始真实代码试运行。
