# Frappe Docker 部署总结（内网 IP 访问版）

本文总结本次在服务器上完成的实际部署过程。当前结果：已可通过内网 IP 正常访问。

## 1. 当前可用访问方式

- 访问地址：`http://172.16.200.44:9090`
- 部署模式：`noproxy`（不走 Traefik/HTTPS，先用于内网联调）

## 2. 最终使用的配置组合

- 基础文件：`compose.yaml`
- 覆盖文件：
  - `overrides/compose.mariadb.yaml`
  - `overrides/compose.redis.yaml`
  - `overrides/compose.noproxy.yaml`
- 生成文件：`~/gitops/erpnext-ip.yaml`
- 项目名：`erpnext`

## 3. 最终环境变量（关键项）

文件：`~/gitops/erpnext.env`

```env
DB_PASSWORD=123
FRAPPE_SITE_NAME_HEADER=172.16.200.44
HTTP_PUBLISH_PORT=9090
```

说明：

- `DB_PASSWORD` 是 MariaDB root 密码（本次实际值为 `123`）。
- `FRAPPE_SITE_NAME_HEADER` 固定为 IP，解决按 Host 匹配站点导致的 `Not Found`。
- `HTTP_PUBLISH_PORT=9090`，所以访问端口为 `9090`。

## 4. 实际执行命令（可复用）

### 4.1 生成部署 YAML

```bash
cd ~/gitops/frappe_docker
docker compose --project-name erpnext \
  --env-file ~/gitops/erpnext.env \
  -f compose.yaml \
  -f overrides/compose.mariadb.yaml \
  -f overrides/compose.redis.yaml \
  -f overrides/compose.noproxy.yaml \
  config > ~/gitops/erpnext-ip.yaml
```

### 4.2 启动容器

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml up -d
```

### 4.3 创建站点

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench new-site 172.16.200.44 \
--mariadb-user-host-login-scope=% \
--db-root-username root \
--db-root-password '123' \
--admin-password 'Admin@123456' \
--install-app erpnext
```

### 4.4 验证

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend bench list-sites
curl -I http://172.16.200.44:9090
```

### 4.5 发布后标准动作（不进入容器开发）

生产发布统一采用“构建镜像 -> 推送 -> 修改 `CUSTOM_TAG` -> `pull + up -d`”。  
不要在运行中的容器内拉代码或临时改代码。


## 5. 本次问题与处理记录

### 问题 1：`Not Found` / `172.16.200.44 does not exist`

原因：请求 Host 为 `172.16.200.44`，但没有对应站点或未设置站点头映射。  
处理：设置 `FRAPPE_SITE_NAME_HEADER=172.16.200.44`，并创建同名站点。

### 问题 2：`Access denied for user 'root' ... (1045)`

原因：创建站点时使用的 `--db-root-password` 与实际 `DB_PASSWORD` 不一致（误用了 `psp.local`，实际为 `123`）。  
处理：统一使用 `DB_PASSWORD=123` 并在 `new-site` 中显式传 `--db-root-username root --db-root-password '123'`。

### 问题 3：命令被拆行导致未执行子命令

原因：Shell 中续行位置不当，执行成 `bench` 帮助页而不是 `bench list-sites`。  
处理：使用单行命令或确保 `\` 续行后参数完整。

## 7. 安装私有应用（product_sales_planning）

目标仓库：

- `https://github.com/jack571754/product_sales_planning.git`
- 分支：`main`

### 7.1 问题说明

执行 `bench get-app` 时出现：

- `Invalid username or token`
- `Password authentication is not supported for Git operations`

原因：GitHub 已禁用账号密码拉取仓库，私有仓库必须使用 `PAT` 或 `SSH`。

### 7.2 方案 A：使用 PAT（推荐快速落地）

在 GitHub 创建 PAT（需包含目标私有仓库读取权限），然后执行：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench get-app --branch main https://github.com/jack571754/product_sales_planning.git
```

安装应用到当前站点：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench --site 172.16.200.44 install-app product_sales_planning
```

迁移并清缓存：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench --site 172.16.200.44 migrate

docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench --site 172.16.200.44 clear-cache
```

验证安装：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench --site 172.16.200.44 list-apps
```

### 7.3 方案 B：使用 SSH（推荐长期）

1. 在 `backend` 容器生成 SSH 公钥。
2. 将公钥加入 GitHub（账号 SSH key 或仓库 Deploy key）。
3. 使用 SSH 地址拉取：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench get-app --branch main git@github.com:jack571754/product_sales_planning.git
```

后续安装、迁移、验证命令与方案 A 相同。

### 7.4 常见错误与处理

1. `Invalid username or token`：PAT 无效、过期或权限不足。
2. `Repository not found`：当前账号/PAT 没有该私有仓库权限。
3. `App not in apps.txt` 或 app 名不匹配：检查仓库内实际 `app_name`，按真实 app 名执行 `install-app`。

## 9. 旧环境数据备份与迁移到新项目

本节适用于“同一服务器存在旧环境，需要迁移到当前新项目”的场景。

### 9.1 迁移原则

1. 新环境先安装与旧站点一致的应用，再恢复数据。
2. 推荐先做同主版本迁移（例如 v15 -> v15），验证后再升级。
3. 恢复会覆盖目标站点数据库，先备份新站点。

### 9.2 是否可以用后台导出备份

可以。若旧项目字段无变化，可直接在旧站点后台导出后上传恢复。  
建议导出 3 类文件：

- `*-database.sql.gz`
- `*-files.tar`
- `*-private-files.tar`

### 9.3 命令行迁移（推荐，可复现）

先设置变量：

```bash
OLD_PROJECT=frappe-old
OLD_FILE=/path/to/old/docker-compose.yml
OLD_SITE=old.site.com

NEW_PROJECT=erpnext
NEW_FILE=~/gitops/erpnext-ip.yaml
NEW_SITE=172.16.200.44

MIG_DIR=~/gitops/migration
mkdir -p "$MIG_DIR"
```

1. 在旧环境生成备份：

```bash
docker compose --project-name $OLD_PROJECT -f $OLD_FILE exec backend \
bench --site $OLD_SITE backup --with-files
```

2. 查看备份文件名：

```bash
docker compose --project-name $OLD_PROJECT -f $OLD_FILE exec backend \
bash -lc "ls -lt sites/$OLD_SITE/private/backups | head -n 10"
```

3. 从旧环境下载到宿主机：

```bash
docker compose --project-name $OLD_PROJECT -f $OLD_FILE cp \
backend:/home/frappe/frappe-bench/sites/$OLD_SITE/private/backups "$MIG_DIR"
```

4. 上传到新环境容器：

```bash
docker compose --project-name $NEW_PROJECT -f $NEW_FILE cp \
"$MIG_DIR/backups" backend:/tmp/migration
```

5. 在新环境恢复：

```bash
docker compose --project-name $NEW_PROJECT -f $NEW_FILE exec backend \
bench --site $NEW_SITE restore /tmp/migration/backups/<database.sql.gz> \
--with-public-files /tmp/migration/backups/<files.tar> \
--with-private-files /tmp/migration/backups/<private-files.tar>
```

6. 恢复后收尾：

```bash
docker compose --project-name $NEW_PROJECT -f $NEW_FILE exec backend \
bench --site $NEW_SITE migrate

docker compose --project-name $NEW_PROJECT -f $NEW_FILE exec backend \
bench --site $NEW_SITE clear-cache

docker compose --project-name $NEW_PROJECT -f $NEW_FILE restart \
backend websocket queue-short queue-long scheduler frontend
```

### 9.4 后台导出后的恢复方式

如果你是从 Frappe 后台下载备份文件（例如先下载到本机），只需要把文件放进新环境 `backend` 容器，再执行恢复命令即可：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml cp \
/path/to/local/backups backend:/tmp/migration

docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench --site 172.16.200.44 restore /tmp/migration/<database.sql.gz> \
--with-public-files /tmp/migration/<files.tar> \
--with-private-files /tmp/migration/<private-files.tar>
```

### 9.5 常见问题

1. `ModuleNotFoundError`：新环境未先安装旧站点使用的 app。
2. `Access denied (1045)`：`DB_PASSWORD` 与实际 MariaDB root 密码不一致。
3. 恢复后页面 500：执行 `migrate`、`clear-cache`，并检查 `backend` 日志。
4. 恢复后资源异常：执行 `bench build --app <app_name>` 后重启 `frontend/backend`。

## 10. 云原生发布（Custom Image，不进容器改代码）

### 10.1 容器挂掉后代码会不会丢

- 会丢：代码只在容器可写层（`docker exec` 进容器后临时改）。
- 不会丢：代码在宿主机挂载目录（开发模式）或已打包到镜像（生产推荐）。
- 本项目生产建议：使用自定义镜像发布（Immutable Infrastructure）。

### 10.2 一次标准发布流程

1. 在构建机准备 `apps.json`（不要提交带 PAT 的文件到 Git）：

```json
[
  {
    "url": "https://github.com/jack571754/product_sales_planning.git",
    "branch": "main"
  }
]
```

2. 生成 base64 参数：

```bash
export APPS_JSON_BASE64=$(base64 -w 0 apps.json)
# macOS 可用：export APPS_JSON_BASE64=$(base64 apps.json | tr -d '\n')
```

3. 构建自定义镜像（示例标签 `16.7.3-psp2`）：

```bash
docker build \
  --build-arg=FRAPPE_PATH=https://github.com/frappe/frappe \
  --build-arg=FRAPPE_BRANCH=version-16 \
  --build-arg=APPS_JSON_BASE64=$APPS_JSON_BASE64 \
  --tag=registry.example.com/erpnext-custom:16.7.3-psp2 \
  --file=images/layered/Containerfile .
```

4. 推送镜像到仓库：

```bash
docker push registry.example.com/erpnext-custom:16.7.3-psp2
```

5. 在服务器更新环境变量并重建：

```bash
cat >> ~/gitops/erpnext.env <<'EOF'
CUSTOM_IMAGE=registry.example.com/erpnext-custom
CUSTOM_TAG=16.7.3-psp2
PULL_POLICY=always
EOF

cd ~/gitops/frappe_docker
docker compose --project-name erpnext \
  --env-file ~/gitops/erpnext.env \
  -f compose.yaml \
  -f overrides/compose.mariadb.yaml \
  -f overrides/compose.redis.yaml \
  -f overrides/compose.noproxy.yaml \
  config > ~/gitops/erpnext-ip.yaml

docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml pull
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml up -d
```

6. 仅在有数据库结构变化时执行迁移：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench --site 172.16.200.44 migrate
```

7. 验证：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bench --site 172.16.200.44 list-apps

curl -I http://172.16.200.44:9090
```

### 10.3 是否需要 `bench build`

- 不需要额外执行：使用上述 `images/layered` 构建流程时，镜像构建阶段已完成资产构建。
- 需要执行：你在运行中容器临时修改了前端资源，且未重新构建镜像。

### 10.4 快速回滚

将 `CUSTOM_TAG` 改回上一个可用标签（如 `16.7.3-psp1`），然后：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml pull
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml up -d
```
