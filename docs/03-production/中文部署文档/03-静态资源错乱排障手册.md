# 静态资源错乱排障手册（内网 IP 部署）

## 1. 适用场景

- 发布后页面可打开，但样式错乱、JS/CSS 404、控制台报静态资源加载失败。
- `bench --site <site> migrate` 成功，服务状态也正常，但前端显示异常。
- 典型于以下部署方式：
  - `docker compose ... config > ~/gitops/erpnext-ip.yaml`
  - `docker compose -f ~/gitops/erpnext-ip.yaml pull && up -d`

## 2. 现象特征

- 登录页或桌面页面 UI 错位。
- 浏览器网络面板出现大量 `/assets/...` 404。
- 同一次发布中，后端功能可用，但前端静态文件不完整或哈希不匹配。

## 3. 根因说明

该问题本质是代码版本与静态资源卷版本不一致：

1. 当前编排中 `frontend` 从独立卷 `/home/frappe/frappe-bench/sites/assets` 提供静态资源。
2. 镜像更新后，后端和模板已切到新版本，但 `sites/assets` 卷可能仍保留旧版本文件。
3. 页面引用的是新哈希文件名，磁盘仍是旧文件，导致 404 和样式错乱。

补充说明：

- 使用 `images/layered` 构建流程时，通常不需要在生产容器里额外执行 `bench build`。
- 在生产容器内重复 `bench build` 可能进一步放大 assets 漂移风险。

## 4. 修复步骤（已验证）

以下操作不会删除数据库卷，仅重建静态资源卷。

1. 查看 `frontend` 挂载卷，识别 `sites/assets` 对应卷名：

```bash
docker inspect erpnext-frontend-1 --format '{{range .Mounts}}{{println .Destination "->" .Name}}{{end}}'
```

2. 停止项目容器：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml down
```

3. 删除 `sites/assets` 对应卷（不要删除 `sites` 或 `db` 卷）：

```bash
docker volume rm <assets_volume_name>
```

4. 重新拉起服务：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml up -d
```

5. 清理站点缓存并重启关键服务：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend \
bash -lc "bench --site 172.16.200.44 clear-cache && bench --site 172.16.200.44 clear-website-cache"

docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml restart frontend backend websocket
```

6. 若 `docker volume rm` 提示卷被占用，先定位占用容器：

```bash
docker ps -a --filter volume=<assets_volume_name>
```

## 5. 发布预防策略

1. 发布流程固定为：`pull -> up -d -> migrate`，避免在生产容器常规执行 `bench build`。
2. 每次发布使用新 tag，不复用旧 tag。
3. `erpnext.env` 中仅保留一组 `CUSTOM_IMAGE/CUSTOM_TAG`，避免镜像来源混乱。
4. 发布后固定执行自检：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml ps
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml exec backend bench --site 172.16.200.44 list-apps
curl -I http://172.16.200.44:9090
```

## 6. 回滚策略

如修复后仍异常，回滚到上一个可用镜像 tag：

1. 修改 `~/gitops/erpnext.env` 的 `CUSTOM_TAG` 为上一个稳定版本。
2. 重新执行：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml pull
docker compose --project-name erpnext -f ~/gitops/erpnext-ip.yaml up -d
```
