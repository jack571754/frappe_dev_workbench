# Frappe Docker 服务器生产部署方案（单机版）

本文基于当前仓库 `frappe_docker`，给出一套可直接落地的生产部署流程。  
推荐方案：`Traefik + Let's Encrypt + MariaDB + Redis + ERPNext`。

## 1. 目标架构

- 单台 Linux 服务器（建议 Ubuntu 22.04/24.04）
- 通过 Docker Compose 启动 Frappe 服务栈
- 使用以下编排文件：
  - `compose.yaml`
  - `overrides/compose.mariadb.yaml`
  - `overrides/compose.redis.yaml`
  - `overrides/compose.https.yaml`
- 域名 HTTPS 访问（自动证书）

## 2. 前置条件

1. 域名 A 记录已解析到服务器公网 IP（示例：`erp.example.com`）。
2. 安全组/防火墙放行端口：`80/tcp`、`443/tcp`（以及 `22/tcp`）。
3. 服务器已安装：
   - Docker
   - Docker Compose v2
4. 具备 sudo 权限。

## 3. 准备目录与代码

```bash
mkdir -p ~/gitops ~/gitops/backups
cd ~/gitops
git clone https://github.com/frappe/frappe_docker.git
cd frappe_docker
```

## 4. 准备环境变量

```bash
cp example.env ~/gitops/erpnext.env
```

编辑 `~/gitops/erpnext.env`，至少设置以下变量：

```env
DB_PASSWORD=<强密码>
LETSENCRYPT_EMAIL=ops@example.com
SITES_RULE=Host(`erp.example.com`)
ERPNEXT_VERSION=v16.7.3
```

可选变量：

```env
HTTP_PUBLISH_PORT=80
HTTPS_PUBLISH_PORT=443
```

## 5. 生成并校验最终 Compose 文件

```bash
cd ~/gitops/frappe_docker
docker compose --project-name erpnext \
  --env-file ~/gitops/erpnext.env \
  -f compose.yaml \
  -f overrides/compose.mariadb.yaml \
  -f overrides/compose.redis.yaml \
  -f overrides/compose.https.yaml \
  config > ~/gitops/erpnext.yaml
```

若命令无报错，即配置层通过。

## 6. 启动服务

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml up -d
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml ps
```

查看关键日志：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml logs --tail=200 backend
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml logs --tail=200 frontend
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml logs --tail=200 db
```

## 7. 初始化站点

确保 `db` 就绪、`configurator` 已成功退出后执行：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml exec backend \
  bench new-site --mariadb-user-host-login-scope=% \
  --db-root-password '<与 DB_PASSWORD 一致>' \
  --admin-password '<管理员强密码>' \
  --install-app erpnext \
  erp.example.com
```

## 8. 上线验证

```bash
curl -I https://erp.example.com
```

浏览器访问 `https://erp.example.com`，使用 `Administrator` 登录。

## 9. 备份与升级

### 9.1 备份（建议定时任务）

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml exec backend \
  bench --site all backup --with-files
```

建议用 crontab 每 6 小时执行一次，并将备份目录同步到对象存储。

### 9.2 升级流程

1. 修改 `~/gitops/erpnext.env` 中版本变量。
2. 重新生成配置：

```bash
docker compose --project-name erpnext \
  --env-file ~/gitops/erpnext.env \
  -f compose.yaml \
  -f overrides/compose.mariadb.yaml \
  -f overrides/compose.redis.yaml \
  -f overrides/compose.https.yaml \
  config > ~/gitops/erpnext.yaml
```

3. 拉取并重启：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml pull
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml up -d
```

4. 执行站点迁移：

```bash
docker compose --project-name erpnext -f ~/gitops/erpnext.yaml exec backend \
  bench --site erp.example.com migrate
```

## 10. 故障排查顺序（推荐）

1. 配置层：`docker compose ... config` 是否通过
2. 依赖层：`db`、`redis` 是否先于 `backend` 就绪
3. 应用层：`backend` 是否有迁移失败/权限错误/连接错误
4. 网关层：`frontend` 是否出现 502 或静态资源 404
5. 网络层：域名解析、80/443 端口、证书签发是否正常

## 11. 可选扩展

- 多站点（单 bench）：调整 `SITES_RULE` 为多个 `Host(...)`
- 多 bench（单机）：使用 `compose.multi-bench.yaml` 与 `compose.multi-bench-ssl.yaml`
- 自定义域映射：使用 `compose.custom-domain.yaml` 与 `compose.custom-domain-ssl.yaml`
